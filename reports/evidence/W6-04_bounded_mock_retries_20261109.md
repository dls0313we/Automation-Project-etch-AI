# W6-04 준비: 최대 4회 모의 재시도 검증

날짜: 2026-11-09

## 범위와 한계

프로젝트 [ADR-0002](https://github.com/dls0313we/Automation-Project-etch-AI/blob/8575ff5f758f07886cf4f73a379a0da868adaaa8/docs/adr/0002-auto-retry-retrain-loop.md)의
최대 4회 재시도 방향을 독립 프로토타입에서 시연했다.
실제 C8/W6-04 작업 전체 완료, 학습 성능 개선 또는 배포 성공의 근거가 아니다.

새 실행기는 기존 판정기와 모의 실행기를 호출한다. 기존 판정 로직·임계치·실제 자료 연결기는 수정하지 않았다.
모의 실행기는 미리 작성한 가상 평가값을 반환한다.
학습 설정 변경이 실제 성능을 개선시켰다고 주장하지 않는다.
PASS/BLOCK은 프로토타입 후보 판정의 요약이며 실제 C5 골든셋 게이트를 호출하지 않는다.
레지스트리·서빙 포인터·가중치 파일은 생성하거나 변경하지 않는다.

## 추가 파일

- `retry_retrain_loop.py`: 횟수 제한, 성능 미달 시 다음 계획, 통과 조기 종료, 오류 즉시 중단, 기록.
- `test_retry_retrain_loop.py`: 새 동작 검사 18개.
- `retry_loop_inputs/scenarios.json`: 기존 가상 입력을 조합한 6개 시연.
- README·CLAUDE: 실행 방법, 전체 206개 검사 명령, 모의 실행 범위.

## 실행 및 관측

```text
python -m unittest -q test_controller.py test_inspect_results.py test_harness.py test_fno_adapter.py test_mgn_adapter.py test_run_review.py test_mgn_geometry.py test_mgn_gt_overlay.py test_fno_gt_overlay.py test_mock_retrain_loop.py test_fno_sdf_compare.py test_fno_chamfer_compare.py test_retry_retrain_loop.py
python retry_retrain_loop.py
```

Python 3.12.14에서 총 206개 검사 통과(기존 188 + 새 18, 4.221초, OK).
최초에는 새 모듈이 없어 검사 실패를 확인한 뒤 구현했다.
실제 모델 정확도를 검사한 수치가 아닌 프로그램 동작 검사 수다.

| 시연 | 실제 모의 호출 수 | 관측 결과 |
|---|---:|---|
| 1차 미달, 2차 통과 | 2 | 교체 권고 후 종료, 3차 호출 없음 |
| 1~3차 미달, 4차 통과 | 4 | 교체 권고 후 종료 |
| 4회 모두 미달 | 4 | 기존 모델 유지, 5차 호출 없음 |
| 임시 기준 | 0 | HOLD, 시작 안 함 |
| 후보 필수 점수 누락 | 1 | 중단, 다음 시도 없음 |
| 모의 실행기 실패 | 1 | 중단, 다음 시도 없음 |

6/6개 상황이 예상과 일치했다. 전체 시도에서 실제 데이터 생성·학습·모델 교체는 False다.
원본·후보 평가 데이터 불일치, 정답 미검증, 실제 자료 입력 거부 등은 별도 단위 검사로 확인했다.
모든 후보는 실패한 직전 후보가 아닌 같은 기존 모델과 비교한다.

## 학습 계획 표시

1차: 조건 40개 / 5 epoch / 학습률 0.001.
2차: 조건 100개(추가 생성 계획 60) / 5 epoch / 0.001.
3차: 조건 100개 / 12 epoch / 0.001.
4차: 조건 100개 / 12 epoch / 0.0005.

이 숫자는 ADR 방향을 참고한 시연용 제안이다. 실제 데이터 수집·분할·생성·학습을 하지 않았다.
검증 데이터와 정책은 시도 중 고정한다. 실제 환경의 골든셋·드리프트 데이터 연결은 후속 작업이다.

## 변경 및 정적 검사 근거

- 작업 전 SHA256을 저장한 기존 Python·임계치·모의 JSON 입력 38개가 모두 동일하다.
- 새 Python 파일 2개는 프로젝트 Ruff 설정으로 검사 통과했다.
- 기존 로컬 코드에는 254개 정적 검사 지적이 남아 있어 이 폴더 전체 lint 통과를 주장하지 않는다.
  기존 파일 해시가 같으므로 이번 변경으로 발생한 지적이 아니다.
  앞서 GitHub에 올린 별도 정리본과 이 로컬 실행 폴더의 서식 차이를 구분한다.
- 기존 실제 FNO/MGN 입력이나 임시 기준, HOLD 상태를 변경하지 않았다.
- 이번 추가 작업은 로컬에만 저장했다. GitHub push·PR 생성·main 변경은 하지 않았다.

## 후속 연결

실제 학습 실행기의 입력·체크포인트·실패 규약, 고정 val 및 golden_drift 평가,
C5 게이트와 레지스트리 승격·서빙 전환을 연결해야 실제 재학습 루프가 된다.
형상 검사와 지표 정의를 먼저 정리하고, 공식 임계치가 정해지기 전 실제 실행 승인을 우회하지 않는다.
