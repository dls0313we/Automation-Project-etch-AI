# FNO 평가 정의 확인 기록

출처: 2026-11-09 사용자가 전달한 민서 답변. 제공자 설명을 기록한 것으로 독립 재현 또는 모델 합격의 근거와 구분합니다.

## 정답 경계와 깊이

- 정답은 원본 VTP 선분이 아니라 정답 SDF의 φ=0 등고선입니다.
- 격자 크기는 [y,x]=[128,256], x 범위 −15~15 µm, y 범위 −68~21 µm입니다.
- `skimage.find_contours`로 격자 사이를 선형 보간합니다.
- SDF 제작 시 마스크–실리콘 내부 경계를 제외해 공기에 드러난 표면만 사용합니다.
- 제공자에 따르면 원본 VTP 표면과의 표면점 평균 차이는 약 0.004 µm입니다. 이 평균의 표본·거리 집계는 독립 검증하지 않았습니다.
- Chamfer와 깊이는 경계를 0.1 µm 간격으로 재표본화한 점으로 계산합니다.
- 깊이 d = −min(y), 실리콘 윗면은 y=0입니다.
- Chamfer의 방향별 합산 정의는 기존 샘플 README 기록을 유지합니다. 이번 답변으로 합산 방식을 새로 바꾸지 않습니다.

## CD(폭)

- 위·중간·바닥 측정 높이는 y=−0.1d, −0.5d, −0.9d입니다. d는 정답 깊이입니다.
- 예측과 정답에 같은 높이를 적용합니다. 예측 깊이로 측정 높이를 바꾸지 않습니다.
- 해당 수평선에서 x=0을 포함하는 공기(φ>0) 구간 길이를 폭으로 사용합니다.
- 양 끝 φ=0 위치를 선형 보간합니다.
- 예측이 해당 높이까지 파이지 않아 x=0이 고체면 예측 폭은 0입니다.
- 오차(%) = 100×(예측 폭−정답 폭)/정답 폭입니다. 정답 폭이 양수이면 예측 폭 0은 −100%입니다.
- 정답 폭이 0인 경우 이 식은 정의되지 않습니다. 제공 CSV의 빈칸을 0이나 −100%로 채우지 않습니다.
- r0307 rollout 마지막 단계의 제공 바닥 폭 오차 약 −23.12%는 정답 깊이의 90% 높이에서 폭이 약 23.12% 좁다는 의미입니다. 음수 자체가 데이터 오류는 아닙니다.

## 이번에 달라진 것과 남은 작업

기존 미확인 항목이던 정답 경계 종류와 CD 측정 높이는 제공자 확인으로 옮겼습니다. 어댑터 입력 JSON과 보고서에 확인 출처를 남깁니다.

현재 비교 그림은 원본 VTP와 예측 SDF 경계를 겹친 보조 진단입니다. VTP에는 내부 재료 경계가 포함될 수 있으므로 민서의 SDF 대 SDF 평가와 동일하지 않습니다. 진단 깊이는 추출 꼭짓점의 최저점이며 제공 깊이는 재표본화 점 기준이라는 차이도 있습니다. 이 설명만으로 개별 점수 차이의 원인이 모두 증명된 것은 아닙니다.

현재 샘플 NPZ는 예측 SDF입니다. 평가에 사용한 정답 SDF를 확보하고 같은 경계 추출·재표본화·폭 계산을 적용해야 독립 점수 재현이 가능합니다. 이는 현재 중간 모델을 이용한 하네스 연결 시연을 막지 않습니다. 최종 결과 검증 때 요청할 수 있습니다.

원본 점수·임계치·집계·평가 계약 ID·판정 코드는 변경하지 않습니다. `reference_verified=false`, 공식 판정 HOLD, 실제 학습·교체 미실행을 유지합니다. 0.004 µm는 합격 임계치가 아닙니다.

## Team-GOAT 허깅페이스 저장소 확인 (2026-11-09)

- [팀 원본 데이터셋](https://huggingface.co/datasets/Team-GOAT/etch-ai-automation-data)의 설명은 `etch-raw-n400.zip`에 원본 VTP와 메타데이터가 있으며, SDF/그래프 ETL 결과는 포함하지 않는다고 명시합니다.
- [파일 상세](https://huggingface.co/datasets/Team-GOAT/etch-ai-automation-data/blob/main/etch-raw-n400.zip)의 SHA256은 `4df39525896536a84e5337dfe196833c7497b6215865c0fc93c1bda87f64b011`입니다. 이미 비교에 사용한 로컬 ZIP도 다시 계산해 같은 해시임을 확인했습니다. 추가 원본 다운로드는 필요하지 않습니다.
- 팀 저장소에는 `code5312/etch-ai-automation-data`에서 복제했다는 커밋 기록이 있습니다. 기존 로컬 출처 기록은 당시 다운로드 이력으로 유지합니다.
- 확인 시점의 [팀 FNO 파일 목록](https://huggingface.co/Team-GOAT/etch-ai-automation-FNO/tree/main)에는 `.gitattributes`와 `README.md`만 있어 평가용 정답 SDF를 찾지 못했습니다. 다른 비공개 저장 위치까지 부재를 확인한 것은 아닙니다.
- 민서가 원본 데이터를 받아 FNO용 SDF로 변환했을 가능성은 있으나, 실제 변환 위치와 코드는 이번 답변만으로 확정할 수 없습니다. 재현 시에는 평가에 사용한 정답 SDF 또는 동일한 전처리 코드·설정을 확보해야 합니다.
