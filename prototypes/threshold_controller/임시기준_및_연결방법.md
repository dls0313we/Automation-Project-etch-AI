# 평가 결과 수신 전 임시 기준

수민님 결과를 받기 전에는 기존 가상 평가 파일과 시연용 임계치로 개발한다.
지표 계산은 외부 평가기가 담당하고, 하네스는 받은 점수를 비교하고 기록한다.
아래 정의는 연결 형식을 준비하기 위한 가정이며 실제 MGN/FNO 평가기에서 확인한 정의가 아니다.

## 임시 지표 정의

| 입력 키 | 가정한 의미 | 단위 | 좋은 방향 |
|---|---|---|---|
| `mean_chamfer_um` | 예측 경계와 정답 경계 사이의 평균 형상 오차 | µm | 작을수록 좋음 |
| `depth_mae_um` | 예측과 정답의 깊이 차이의 절댓값을 평균한 값 | µm | 작을수록 좋음 |
| `invalid_geometry_count` | 형상 검사에 실패한 예측 프레임 수 | 건 | 0이 좋음 |

형상 오차는 임시로 '예측 점 → 최근접 정답 점의 거리 평균 + 정답 점 → 최근접 예측 점의 거리 평균'으로 정의한다.
거리는 제곱하지 않으며 두 방향 평균을 더한 뒤 2로 나누지 않는다.
깊이 오차는 임시로 두 경계의 최소 y 좌표 차이의 절댓값으로 정의한다.
실리콘만을 골라 계산하는 깊이 지표와는 정의가 다를 수 있다.
평균 지표는 레시피 안에서 시간 단계 평균을 구한 뒤, 레시피 평균들을 동일 가중치로 평균한다고 가정한다.
one-step과 rollout은 따로 집계하고, 평가 데이터의 split도 섞지 않는다.

형상 이상 건수는 좌표 비정상, 잘못된 연결, 자기교차 등의 검사 중 하나라도 실패한 프레임을 한 번씩 센다고 가정한다.
이 문서와 현재 하네스는 해당 형상 검사나 점수 계산을 구현하지 않는다.
원본 입력의 오류를 뜻하는 `data_check.invalid_recipe_count`와 예측 형상의 오류를 뜻하는 `invalid_geometry_count`는 별개이다.
측정하지 않은 점수는 입력에서 누락하거나 null로 두며 0으로 대신하지 않는다. 필수 점수가 없으면 HOLD이다.

FNO는 출력에서 어떤 경계를 추출할지와 단위 복원 방식이 아직 미확인이다.
현재 FNO 점수는 가상 숫자이며 위 정의로 실제 FNO 결과를 측정했다는 뜻이 아니다.

## 기준값: 기존 기본 설정 재사용

실제 실행 기준은 `thresholds_demo.json`의 `policies`이다.

| 모델 | 방식 | 형상 오차 상한 (µm) | 깊이 오차 상한 (µm) | 형상 이상 상한 (건) |
|---|---|---:|---:|---:|
| MGN | onestep | 0.20 | 0.50 | 0 |
| MGN | rollout | 0.50 | 1.00 | 0 |
| FNO | onestep | 0.25 | 0.60 | 0 |
| FNO | rollout | 0.60 | 1.20 | 0 |

관측값이 상한과 같으면 통과하며, 상한보다 크면 초과이다.
이 숫자와 모델별 차이는 판정 분기를 보여주기 위해 임의로 정한 값이다.
공정 허용 오차, 실제 성능 분포, 모델 간 우열을 근거로 정한 값이 아니다.

`thresholds_demo_relaxed.json`은 임계치 조정 시연용 별도 설정이다.
MGN rollout 형상 오차 상한 0.80, 기준 버전 `demo-MGN-rollout-v2-relaxed`를 사용한다.
기본 실행은 계속 `thresholds_demo.json`을 사용한다.

## 판단 순서와 준비 상태

1. 데이터 점검 실패: DATA_REVIEW.
2. 필수 정보/점수 누락, 단위 불일치, 기준 미승인 등: HOLD.
3. 필수 점수가 모두 기준 이내: KEEP_CURRENT.
4. 기준 초과이며 승인된 학습 데이터 준비 완료: RETRAIN_REQUEST.
5. 기준 초과이며 학습 데이터 미준비: WAIT_FOR_TRAINING_DATA.

후보 모델 비교는 별도 분기다. 같은 고정 validation 데이터와 계산 방식으로 비교한다.
후보가 모든 상한을 통과하고, 필수 지표가 악화되지 않으며, 주 지표가 최소 5% 개선되면 APPROVE_CANDIDATE를 권고한다.
현재 실행기는 재학습이나 모델 교체를 수행하지 않는다.
가상 자료의 `reference_verified=true`와 `training_data_ready=true`는 시나리오 설정일 뿐 실제 확인 결과가 아니다.
실제 자료에서는 근거 없이 해당 값을 true로 채우지 않는다.

## 나중에 바꿀 위치

| 확정될 내용 | 수정 위치 |
|---|---|
| 평가 결과의 실제 키와 파일 형식 | 수민님 결과를 기존 `harness_inputs/evaluations/` 예시 형식으로 변환하는 연결 부분 |
| 지표 이름과 단위 | 평가 입력의 `metrics`, `metric_units` 및 기준 파일의 대응 키 |
| 계산 방식, 경계 정의, 집계 방식 | 위 임시 정의를 확정 정의로 교체하고 입력/정책의 `evaluation_contract_id`를 함께 갱신 |
| 허용 오차와 후보 개선 조건 | 별도 기준 파일의 `max_metrics`, `min_primary_improvement_relative`, `max_relative_regression` |
| 기준값 변경 이력 | 정책의 `version`; 기존 실행 결과는 보존 |

임계치만 바뀌고 계산 방식은 같으면 `evaluation_contract_id`는 유지한다.
실제 기준은 팀에서 합의한 뒤 새 파일에 기록한다. 현재 시연용 숫자를 그대로 승인된 기준으로 바꾸지 않는다.
실제 입력에는 실제 출처를 기록하며, 현재 demo 정책은 실제 점수를 합격/불합격으로 판정하지 않는다.

## 실행

```text
python harness.py --demo
```

현재 결과는 가상 점수로 판정 흐름을 검증한 기록이다. 실제 모델 정확도 검증과 평가기 연결은 이후 단계다.
